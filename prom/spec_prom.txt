Spec 生成硬约束

需求源：PRD 为唯一需求源，wireframe.pen 为页面结构依据；冲突以 PRD 为准；原型缺失标“待确认”；不得臆造。

无法读取 .pen 时，先要求上传可读导出件，不得跳过页面依据。

不扩展 PRD 未定义角色、页面、接口、数据表、业务能力；不设需求优先级；每项可追溯 FR 编号。

技术栈映射：前端 Vue；后端 Python + FastAPI + Uvicorn 仅承载控制面 API 与 Harness 调用入口；Celery、Redis、PostgreSQL、SeaTunnel 按 PRD 交付物建模。

Harness 是本项目核心与不可绕过执行内核。Spec 以 Harness 为主轴建模，不得将其降为普通业务 service。

Harness 子组件独立成章：PDP、Capability Issuer/Verifier、Tool Broker、Replay Guard、Transactional Outbox、Evidence Ledger。每个子组件写清职责、输入、输出、状态、失败码、审计事件、对应 FR。

所有副作用执行只能经 Tool Broker；FastAPI/Uvicorn 不得绕过 Harness 直接执行副作用。

禁止：Secret 明文、密码明文、敏感样本明文、申请人自批、绕过审批直接执行、控制面直连搬运海量业务数据。

每章固定字段

页面：路由、可见角色、页面目标、布局区、核心组件、数据来源接口、页面状态、操作、权限差异、异常提示、对应 FR。

前端模块：模块名、职责、依赖接口、状态管理、交互事件、权限控制、异常处理、对应 FR。

后端模块：模块名、职责、边界、依赖表、对外接口、内部协议、异常码、审计事件、对应 FR。

接口：方法、路径、用途、权限、请求字段、响应字段、错误码、幂等/重放规则、审计要求、对应 FR。

数据表：表名、用途、关键字段、主外键/约束、索引建议、敏感字段、生命周期、对应 FR。

Harness 子组件：职责、输入、输出、状态、失败码、审计事件、对应 FR。

状态机覆盖：三阶段协议、审批状态、执行状态、Capability 5 分钟单次消费、Replay Guard 拒绝、Outbox 投递、Evidence Ledger 哈希链。

验收映射逐条对应 PRD 第 10 节 9 条；Harness 相关验收单列。
