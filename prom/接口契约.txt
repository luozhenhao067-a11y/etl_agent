接口契约生成硬约束

契约基线：只使用 Spec 第 9.2 节 API-01～API-18 与 PRD 第 8 节 18 个接口；不新增路径、不删接口；缺失能力列“待确认”，不补造。

冲突裁决：Spec 与 PRD 冲突以 PRD 为准；Spec 细化不改变路径与语义。

契约定位：契约是前后端、Worker、Harness 之间唯一接口事实源；实现不得偏离契约；契约变更必须版本化。

Harness 标注：每个接口必须标注“是否经 Harness”“是否产生副作用”“是否需要 Capability”“是否写 Evidence Ledger”。

安全边界：契约中不得出现 Secret 明文、密码、Capability 明文、原始敏感样本；示例值必须脱敏。

不设需求优先级；P0-P3 仅指 PDP 风险等级。

契约总则

协议：HTTP/JSON；字符集 UTF-8；时间 ISO 8601 带时区。

版本：路径前缀 /api/v1；破坏性变更升 /api/v2，不原地改语义。

资源标识：路径参数统一 {xxx_id}；响应统一返回 id 与业务键。

命名：字段用 snake_case；枚举值小写蛇形；布尔用 is_ / has_ 前缀。

必填：请求字段标注 required / optional / conditional；conditional 必须写触发条件。

类型：string、integer、number、boolean、object、array、enum；array 必须写 item 类型；object 必须写子字段。

分页：page、page_size、total、items；上限待确认，不擅自定值。

排序：sort_by、sort_order=asc|desc；允许字段白名单。

过滤：显式列出可过滤字段，不允许任意字段过滤。

全局约定

请求头：Authorization、X-Correlation-Id、Idempotency-Key（写接口必填）、Content-Type。

响应头：回传 X-Correlation-Id；不返回服务端版本、内部主机、堆栈。

成功结构：{"data": ..., "correlation_id": "..."}；列表 data 内含 items/total/page/page_size。

错误结构：{"error_code","message","correlation_id","details"}；details 不得含 Secret、令牌、原始敏感值。

状态码：200 成功；201 创建；204 无内容；400 参数；401 未认证；403 无权限；404 不存在；409 冲突/状态不允许；410 过期；413 超限；422 语义校验失败；424 依赖失败；429 限流；500 内部；503 依赖不可用；504 依赖超时。

限流：写接口与 Harness 相关接口必须声明限流维度与阈值；阈值待确认。

审计：每个写接口必须声明至少一条审计事件；只读接口默认不写 Ledger，除非 Spec 明确要求。

脱敏：响应字段必须标注是否脱敏、脱敏规则；不得返回未脱敏样本。

示例：每个接口至少给一个请求示例与一个成功响应示例；失败示例至少给一个；示例值必须脱敏。

认证与授权约定

认证机制待确认 P-26；契约只约定“必须认证”，不约定令牌格式。

项目隔离：所有资源路径必须可归属 project_id；跨项目访问返回 403。

角色校验：按 Spec 2.3 权限矩阵；契约逐接口写“允许角色”“禁止角色”。

职责槽：审批类接口必须写 required_role 与自批拦截规则。

前端隐藏按钮不构成安全边界；服务端必须复核。

错误码总表

按 Spec 第 13.1 节输出，逐条列：error_code、HTTP、含义、可重试、触发条件、所属模块、对应 FR。
不得新增 Spec 未定义错误码；缺失的列“待确认”。

Harness 调用矩阵

输出表格：接口 ID × 是否经 Harness × 调用工具 × 是否签发 Capability × 是否经 Replay Guard × 是否写 Ledger × 禁止绕过说明。
至少覆盖：API-05、API-06、API-07、API-12、API-14、API-16、API-17、API-18。

幂等与重放矩阵

输出表格：接口 ID × 幂等键 × 幂等范围 × 重复请求结果 × 重放保护机制 × 失败是否返还额度。
必须覆盖 Spec 第 13.7 节全部操作。

审计事件映射

输出表格：接口 ID × 审计事件 × 生产者 × payload_digest 覆盖字段 × 是否进 Ledger。
必须与 Spec 第 12.2 节一致，不新增事件类型。

待确认处理

接口缺失：列“待确认接口”，写清被谁需要、阻塞什么、Spec 对应 P 编号。

字段缺失：列“待确认字段”，写清字段用途、类型建议、是否阻塞。

不得以“合理猜测”补字段；不得用前端聚合替代缺失接口。

契约变更规则

契约冻结后，新增字段必须可选且向后兼容。

删除字段、改类型、改语义、改错误码 = 破坏性变更，必须升版本。

错误码只增不改；废弃错误码保留并标注 deprecated。

契约变更必须同步更新：Spec、审计事件、幂等矩阵、验收映射。

输出要求

只输出契约文档；不写过程说明、客套话、总结段。

用表格与清单；不写长段落。

不重复 PRD/Spec 原文；只写契约约束、字段、错误码、幂等、审计、脱敏、追溯编号。

每个接口必须可被前端、后端、Worker、Harness 直接实现与联调。

输出 OpenAPI 3.1 时，必须与逐接口契约表一致；不一致以契约表为准。

示例值必须脱敏；不得出现真实主机、账号、令牌。

输出前自检：

是否覆盖 API-01～API-18；

是否逐接口标注 Harness / Capability / Ledger；

是否覆盖幂等与重放矩阵；

是否错误码与 Spec 13.1 一致；

是否审计事件与 Spec 12.2 一致；

是否出现未定义接口、未定义错误码、敏感明文；

是否把待确认项写成既定事实。

有则删除或改标“待确认”后重写。
