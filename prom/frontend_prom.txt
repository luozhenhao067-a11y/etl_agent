**接口调用约束**

1. 只调用契约 API-01～API-18；不得调用未定义接口。
2. 每个页面文件顶部注释：依赖的 API ID 列表。
3. 请求头必须带 `Authorization`、`X-Correlation-Id`；写接口带 `Idempotency-Key`。
4. 错误统一解析 `{error_code, message, correlation_id, details}`；按 `error_code` 展示脱敏提示，不展示堆栈、主机、Secret、令牌。
5. 401 跳登录；403 显示无权限；409 显示状态冲突；410 显示过期；422 显示字段校验；503/504 显示依赖不可用并可重试。
6. 缺失接口（Spec P-18～P-24）用 mock 适配层，集中放 `src/api/mock/`，并在 README 列清单；不得散落在页面里硬编码假数据。

**权限与角色渲染**

1. 按 Spec 2.3 权限矩阵控制按钮与入口显隐。
2. 角色来源：当前登录用户信息；认证机制待确认 P-26，先用可替换的 `useAuth` 适配层。
3. 前端隐藏按钮不构成安全边界；写操作仍按服务端返回处理。
4. 审批按钮按 `required_role` 与当前用户职责槽显隐；申请人审批按钮禁用并提示“申请人禁止自批”。
5. Ops 才显示 Commit、取消、重跑、回滚、清理；Auditor 全只读、无操作按钮。

**状态展示**

1. 每个页面必须实现：loading、empty、error、forbidden、stale 五态。
2. 列表页增加 filtered-empty；表单页增加 submitting、success、failed。
3. 执行页增加 running、succeeded、failed、cancelled、queued、log-disconnected。
4. 审批页增加 pending、partial-approved、approved、rejected、committing、committed、commit-failed。
5. 状态徽标颜色按 Spec：成功绿、运行中蓝、待审批橙、失败/高风险红、禁用灰。
6. 不得把原型演示数值（200MB、2M 行、5%、10min、99.0 分）写成业务默认值。

**脱敏与安全**

1. Secret、密码、Capability、JTI、token_digest 一律不展示、不写日志、不进 localStorage。
2. 手机号、邮箱、姓名、证件号、主机、JDBC URL 按 Spec 12.3 掩码展示。
3. 错误表样本、文件头、脱敏样本只展示脱敏值。
4. 禁止在前端拼接海量数据聚合替代缺失接口。
5. 禁止实现“跳过审批直接执行”“申请人自批”入口。

**关键交互**

1. 三阶段状态条：`prepare → approve → commit`，展示当前阶段与 2/2 审批状态。
2. Studio 必须展示：LangGraph 步骤时间线、澄清表单、EtlPlan 表、HOCON 代码块（语法高亮）、DAG 容器、字段 Diff、门禁 4 项结果、冻结与提交按钮。
3. 审批页必须展示：Preparation 冻结事实、两个独立审批卡、职责分离提示、Capability 预览（仅摘要）。
4. 运维操作必须二次确认，回滚需输入 `ROLLBACK` 确认词，原因必填。
5. Commit 成功只展示 `execution_run_id`、状态、`capability_digest`，不展示令牌明文。

**轮询与订阅**

Spec P-16 待确认。前端必须把执行状态刷新封装为可替换的 `useRunStatus` 适配层，默认用轮询占位，间隔与是否改订阅在 README 标注“待确认”，不得写死为最终方案。
