**任务一：切换真实后端**

1. 前端 `api/mock` 适配层保留，但通过开关切到真实后端；不删除 mock。
2. `VITE_API_BASE_URL=http://localhost:8000`，写入 `.env.development`，不提交真实密钥。
3. 确认 CORS 允许前端源；不允许 `*` 放开生产。
4. 启动后端 `uvicorn app.main:app --reload`，前端 `npm run dev`。
5. 输出：启动方式、环境变量清单、CORS 配置位置。

**任务二：逐页联调**

按顺序走完 12 个页面，每页固定记录：

| 页面 | 路由 | 调用接口 | 结果 | 问题 |
|---|---|---|---|---|

页面清单：dashboard、connections、profiles、files、studio、preparations、executions、quality、operations、benchmark、evolution（占位）、审计（占位）。

每页必须验证：

1. 请求路径、方法、参数与契约一致。
2. 响应字段名、类型、必填与契约一致。
3. 分页 `page/page_size/total/items` 一致。
4. 成功结构 `{data, correlation_id}` 一致。
5. 错误结构 `{error_code, message, correlation_id, details}` 一致。
6. 状态码与契约一致：400/401/403/404/409/410/413/422/424/429/500/503/504。
7. 五态展示：loading、empty、error、forbidden、stale。
8. 权限按钮显隐与 Spec 2.3 一致。
9. 脱敏字段：手机号、邮箱、主机、JDBC URL、Secret、token_digest。
10. 503 页面展示“依赖未就绪”，不展示堆栈、不假装成功。

**任务三：重点验证清单**

逐项打勾并记录证据（截图/请求响应）：

1. 统一响应结构与错误结构。
2. 分页字段与排序参数。
3. `Authorization`、`X-Correlation-Id` 透传；写接口 `Idempotency-Key` 必填，缺失返回 400。
4. 幂等：同键同载荷返回首次结果；同键不同载荷 409。
5. 权限：401 跳登录、403 无权限页、审批接口自批返回 `APR-403`、职责槽冲突返回 `APR-409`。
6. 脱敏：响应无 Secret、密码、Capability 明文、原始敏感样本。
7. 503：Harness 类接口返回 `error_code` 正确，`details` 含 `dependency` 与 `status`。
8. 占位页：`/governance/evolution` 与审计页只展示空态与“待确认”，不报错、不白屏。
9. 前端不聚合缺失接口、不硬编码假数据。
10. `/docs` 与 `/openapi.json` 可访问，且与契约一致。

**任务四：契约测试**

1. 用 `pytest + httpx.AsyncClient` 对每个已实现接口至少覆盖：成功、参数错误、权限拒绝、依赖未就绪（503）四类。
2. 写接口额外覆盖：缺 `Idempotency-Key` → 400；同键不同载荷 → 409。
3. 审批接口额外覆盖：自批 → `APR-403`；职责槽冲突 → `APR-409`。
4. Harness 接口额外覆盖：返回 503、`error_code` 正确、无假数据。
5. 测试不依赖真实 DB、Redis、SeaTunnel、Vault。
6. 输出测试报告：用例数、通过数、失败数、失败原因。

**输出物**

1. 联调问题清单：页面、接口、字段、现象、期望、严重级别、负责人、状态。
2. 契约偏差记录：契约字段 vs 实际字段，偏差类型（缺失/命名/类型/状态码/错误码），处理建议（改前端/改后端/改契约，改契约需评审）。
3. 联调通过清单：按页面列已跑通接口。
4. 503 接口清单：接口 ID、前端展示效果、是否符合预期。
5. 测试报告。
6. 待确认项：联调中发现的契约未定义或冲突点，标注对应 Spec P 编号。
