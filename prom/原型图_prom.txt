你是一名企业级 B/S 中后台产品原型设计师。请以 `D:\资料\三项\ETL-Agent 数据集成平台\项目信息\需求文档prd.txt` 为**唯一需求依据**，生成“生产级 ETL-Agent 数据集成平台”的 Web 控制台原型图。若无法读取本地文件，请先要求我上传该 PRD。不得引入 PRD 与原文 2.8 节未定义的角色、页面、业务功能或需求优先级。

### 四、逐页原型要求

#### 1. 总览工作台

需展示：
- 当前项目连接数；
- Pipeline 数量；
- 待审批门禁概况；
- 运行成功率；
- 核心资源分布；
- 最近执行与待办审批入口。

要求：
- 使用指标卡片 + 趋势/分布图 + 待办列表组合布局；
- 待审批概况需能区分数据审批与安全审批；
- 运行成功率需展示成功、失败、运行中、已取消等状态分布；
- 提供跳转到运行中心和审批面板的入口。

#### 2. 数据连接与资产页

需包含三个子模块，采用 Tab 或左侧二级导航切换：

1. **连接管理**
   - 连接列表：连接名称、类型、来源/目标、环境、状态、最近测试时间、Secret 保存状态；
   - 操作：新建连接、编辑连接、连接测试、查看详情；
   - 新建/编辑表单需包含数据库连接与文件数据源字段；
   - Secret 字段只展示密文保存状态，不展示明文。

2. **元数据探查**
   - 展示数据表 Schema、字段类型、主键、近似统计指标；
   - 展示脱敏样本视图；
   - 明确标识“只读探查”和“脱敏样本”；
   - 提供发起探查、查看探查结果、刷新状态入口。

3. **文件资产管理**
   - 展示已上传文件：文件名、格式、大小、字段推断状态、更新时间；
   - 支持上传并解析本地/对象存储文件；
   - 展示文件头与字段推断结果。

#### 3. Pipeline Studio（设计与生成工作台）

页面需体现原文四区布局，建议采用“左中右 + 底部”或“主工作区 + 右侧审查区”布局，至少包含：

1. **需求输入区**
   - 自然语言业务需求输入框；
   - 源端 Profile 与目标端 Profile 选择；
   - 发起生成按钮；
   - 当前 Pipeline/版本上下文。

2. **Agent 对话与澄清区**
   - 展示 LangGraph 状态机执行步骤；
   - 展示需求澄清提问与用户回答；
   - 展示交互表单与有限修复过程；
   - 需有“等待补充信息”“已恢复执行”“有限修复中”等状态。

3. **方案与配置审查区**
   - EtlPlan 结构化设计展示；
   - SeaTunnel HOCON 配置代码块，带语法高亮；
   - DAG 拓扑图；
   - 字段映射 Diff；
   - 脱敏前后结构对比；
   - 确定性门禁校验结果：语法校验、Schema 对齐校验、通过/失败原因。

4. **版本与审批提交区**
   - 展示不可变版本号与 SHA256 摘要；
   - 展示调度策略配置；
   - 提供“冻结为不可变版本”“提交审批申请”操作；
   - 提交后展示审批职责槽分配结果：数据审批人、安全审批人。

#### 4. 运行中心

需包含四个功能块：

1. **准备与审批面板**
   - Preparation 准备单；
   - 输入指纹、资源范围、影响范围、数据分级、运行预算、回滚方案；
   - 审批人列表；
   - 数据审批与安全审批的独立审批卡片；
   - 审批决策入口：approve / reject；
   - 明确展示“申请人禁止自批”和“职责分离”提示。

2. **执行与监控**
   - ExecutionRun 列表；
   - 实时运行状态；
   - 读取行数、写入行数、过滤行数；
   - 字节数、执行时长、吞吐量；
   - 实时日志滚动区；
   - SeaTunnel 作业 ID 展示。

3. **质量与诊断报告**
   - 有效数据写入统计；
   - 错误表分流明细；
   - 错误码分布；
   - 质量契约命中情况；
   - 可解释根因诊断；
   - 运行监督指标：记录数、字节数、时长、输出放大比、拒绝率；
   - 越线预警、硬中断、隔离告警状态展示。

4. **运维操作**
   - 任务取消；
   - 安全重跑；
   - 影子表回滚；
   - 清理入口；
   - 所有操作需二次确认弹窗，并展示权限校验结果。

#### 5. 安全治理与 Benchmark 页

需包含：

1. **Benchmark 大盘**
   - 运行自动化 Benchmark 测试集入口；
   - 展示生成准确率；
   - Schema 覆盖率；
   - P0/P1 安全拦截率；
   - 延迟对比；
   - 分层仿真 L0/L1/L2 状态展示。

2. **安全进化管理**
   - Prompt/策略改进候选列表；
   - 审查报告；
   - 小流量/影子授权开关；
   - 受控安全进化闭环状态。

### 五、关键流程原型要求

原型中必须用页面跳转、抽屉、弹窗或状态条串联以下流程：

1. **端到端需求生成与受管执行流程**：
   配置连接 → 元数据 Profile → 输入自然语言需求 → LangGraph 澄清/恢复 → 生成 EtlPlan/HOCON → 确定性门禁 → 冻结不可变版本 → Prepare 准备单 → 数据审批 + 安全审批 → Commit → Capability 签发 → Outbox 投递 → Celery Worker 执行 → SeaTunnel 影子表写入/错误分流 → 运行监督 → 原子 Swap → 证据账本。

2. **任务失败诊断与安全回滚流程**：
   执行异常/监督超限 → 中断并记录失败快照 → 根因诊断与修复建议 → 操作员发起回滚 → Harness 权限校验 → 受管清理恢复。

原型中需明确展示：
- `prepare → approve → commit` 三阶段状态条；
- 四眼原则审批状态；
- Capability 令牌摘要、有效期 5 分钟、单次消费状态；
- Replay Guard 防重放提示；
- Transactional Outbox 投递状态；
- Evidence Ledger 哈希链与签名检查点可视化占位。
