[交付功能]:
统一入口网关：提供唯一协议入口，业务服务必须经此调用，禁止绕过内核直接执行。

PDP 风险决策：根据调用意图、资源与数据分级，输出 P0-P3 风险等级及审批要求。

签发校验令牌：基于 Ed25519 算法，生成并验证单次执行权限的 Capability 短时令牌。

唯一出口防重放：作为所有副作用的唯一出口，拦截未授权调用，并由 Guard 拦截重放请求。

事务发件箱：保证本地业务数据与异步任务投递的原子一致性，确保命令不丢失。

证据防篡改账本：维护关键事件的哈希链与签名检查点，确保审计记录绝对不可篡改。

三阶段协议管控：强制执行准备（Prepare）、审批（Approve）与提交（Commit）的闭环流程。

[具体要求]:

读 Spec 严守边界：严格遵循 Spec 第 3-5 章，只做 Harness，禁止修改现有 API 契约与前端代码。

统一入口网关：封装统一拦截器，路由层禁止直接产生副作用，所有执行请求必须强制走 Harness 入口。

PDP 风险决策：接收执行意图，按资源与数据分级评估，输出 P0-P3 风险与审批槽，策略失败即阻断。

签发校验令牌：基于 Ed25519 签发 5 分钟有效、单次消费的令牌，绑定指纹，仅存摘要不入库明文。

唯一出口防重放：Tool Broker 作为唯一执行出口；基于 Redis 实现原子防重放，重复请求直接拦截。

事务发件箱：Outbox 与业务数据必须同属一个 PostgreSQL 事务提交，确保异步指令绝不丢失。

证据防篡改账本：基于 SHA256 维护哈希链，实现只追加；配置数据库触发器，绝对禁止 UPDATE/DELETE。

三阶段协议管控：严格实现 Prepare、Approve、Commit 状态机，Commit 必须强制校验 2/2 审批与指纹一致。

强制输出格式：按功能模块建独立目录，先给目录结构与实施计划，确认后再分模块输出代码。

测试用例闭环：核心逻辑（如令牌签发/验签、重放拦截、Outbox 事务）必须配套对应的 pytest 单元测试，确保真能跑通。

复用现有依赖：Harness 内部的 Redis 和 PG 连接池，必须复用项目现有的配置（如 session.py），禁止重新建一套连接。

严禁全量直出：必须先出 core/ 和 models/，等我确认没问题，再出 services/ 和 routers/。

异常与降级：Harness 内部报错（如 Redis 连不上）必须 fail-closed（直接拒绝业务），绝不允许静默放行。
