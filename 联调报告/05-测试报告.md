# ETL-Agent 测试报告

- 测试日期：2026-10-23
- 测试对象：`backendpoint/app` 已实现接口 API-01～API-18；另含 Alembic schema 与本地 Harness 内核
- 测试方式：`pytest` + `httpx.AsyncClient` + `ASGITransport` 进程内调用；API 测试不连接真实数据库、Redis、SeaTunnel、Vault；schema 测试使用临时 SQLite，PostgreSQL 迁移另做一次性容器实测；Harness 内核测试使用内存适配器与固定时钟
- 前端构建：`npm run build`

## 〇、启动方式与环境

### 后端

```bash
cd backendpoint
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

本次取证使用无 `--reload` 的进程。Windows 上 `--reload` 曾打印重载日志但未替换子进程，导致旧代码继续服务；最终证据均来自重启后的无重载进程。

- `/docs`：`http://127.0.0.1:8000/docs`
- `/openapi.json`：`http://127.0.0.1:8000/openapi.json`

### 前端

```bash
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173
```

`frontend/.env.development`（仅非敏感开发配置，未提交真实密钥/令牌）：

```env
VITE_API_BASE_URL=http://localhost:8000
VITE_USE_MOCK=false
```

`src/api/mock` 适配层保留；`VITE_USE_MOCK=false` 时 mock 不接管请求，已实现接口直连后端。

### CORS

- 配置默认值：`backendpoint/app/config.py` 的 `cors_origins`，默认 `http://localhost:5173`、`http://127.0.0.1:5173`。
- 中间件：`backendpoint/app/main.py` 的 `CORSMiddleware`，`allow_credentials=True`，允许 `Authorization`、`Content-Type`、`X-Correlation-Id`、`Idempotency-Key`，暴露 `X-Correlation-Id`。
- 生产约束：`Settings.__post_init__` 显式拒绝 `*`；`test_settings_reject_wildcard_cors_origin` 与预检测试通过，预检响应 `Access-Control-Allow-Origin` 为精确前端 Origin，不是 `*`。

### 幂等专项

- 缺 `Idempotency-Key`：11 个写接口逐一断言 `400 API-400`；API-05、API-10 按契约例外。
- 同键同 payload：API-03、API-04、API-13 等断言首次结果重放；API-13 额外确认只写一次审计事件、审批仍为 `approved`。
- 同键不同 payload：参数化覆盖 connections 创建/更新、profiles、pipelines、generation、prepare、审批决策、取消、回滚，断言 `409` 与对应领域冲突码；API-07、API-14、API-18 另有专项用例。
- API-18 冲突：断言 `409 BENCH-409`，`details={"reason":"payload_mismatch"}`。

## 六、限制与说明

- API 测试不依赖真实 DB/Redis/SeaTunnel/Vault，验证的是契约行为与 fail-closed，不是外部系统真实连通性；schema 测试使用临时 SQLite，PostgreSQL 迁移另做一次性容器实测。
- API-05/06/07/12/14/16/17/18 的业务成功路径无法验证，因为 Harness 未实现；测试目标是 503、无副作用、无假数据。
- 契约缺失接口 P-18～P-24 不在测试范围；前端只验证空态与“待确认”。
- 浏览器走查脚本与截图用于本次交付取证，未纳入 `npm test`（项目未配置前端单测/E2E 框架）。
- `page_size` 上限 100、排序未实现属于契约待确认项（P-19/P-35），已登记为非阻塞，详见《02-契约偏差记录》和《06-开放问题》。
- API-02 白名单外 `q` 已由后端拒绝；契约本身没有 `q`，因此不需要“实现 q”或“删除 q”，只需执行既有白名单。
- Alembic 只建 Spec 10.1 / PRD 7.1 的 13 张表；连接配置、Profile、Preparation、Outbox、Capability 消费记录、Benchmark 结果仍未建表，API 运行时仍为内存数据。
- PostgreSQL 触发器与约束已在一次性 `postgres:16-alpine` 容器实测；该容器不是交付环境，生产部署仍需按 P-28 确认版本与拓扑。
- Harness 内核已实现但**未注入 API**；API 仍通过 Stub 返回 503。P-06 Outbox 持久化、P-07 Capability 消费记录、P-09 Ledger 链序、P-31/P-32 密钥与检查点频率仍未闭合，35 项内核测试只证明本地状态机与 fail-closed 行为，详见《08-Harness内核记录》。
