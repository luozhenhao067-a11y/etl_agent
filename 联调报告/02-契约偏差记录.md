## 二、API-02 `q` 收口记录

| 项 | 内容 |
|---|---|
| 契约事实 | API-02 查询参数表仅列 `type`、`env`、`status`、`page`、`page_size`；契约第 487 行明确仅允许白名单字段。契约中没有 `q`，因此不存在“实现 q”或“删除 q”的二选一；正确做法是执行既有白名单。 |
| 缺陷 | FastAPI 默认忽略未声明查询参数，`q=orders` 被静默接受并返回 `200`。 |
| 修复 | `backendpoint/app/api/connections.py` 在权限校验后显式比较 `request.query_params` 与白名单，白名单外参数返回 `400 API-400`，`details.field` 指向第一个未知参数。 |
| 测试 | `tests/test_connections.py::test_api_02_unknown_query_is_rejected` 断言 `400 API-400` 且 `details.field="q"`。 |
| 实机复测 | `GET /api/v1/projects/prj_demo_001/connections?q=orders` 返回 `400 API-400`、`details={"field":"q"}`；证据见 `证据/api_live_sanitized.json` 条目 `API-02 non-contract q rejected`。 |
| 契约变更 | 无。未新增、删除或改名任何查询参数、字段、错误码。 |
