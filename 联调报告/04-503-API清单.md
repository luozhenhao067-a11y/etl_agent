# ETL-Agent 503 API 清单

- 预期：Harness 未就绪时 fail-closed，返回 503；前端显示“依赖未就绪”，不伪造成功、不写假数据。
- 公开错误码以接口契约为准：逐接口领域 503 码，`details.dependency=harness`、`details.status=not_implemented`。
- `HARNESS_NOT_READY` 仅为后端内部哨兵，**禁止**出现在公开 `error_code`；不得把 503 省略或改写为成功路径。
- 口径依据：`项目信息/接口契约.md` 附录 A（按 Spec 8.1/13.1 溯源，details 结构已回写 Spec 9.1）。
- 证据：`证据/flows.json`、`证据/flow_api05.png`～`flow_api18.png`、`证据/api_live_sanitized.json`。

## 口径说明

任务文本写的是 `503 HARNESS_NOT_READY`，但契约第 4 章没有该公开错误码：
- 后端内部桩以 `NotImplementedError("HARNESS_NOT_READY")` 表示未就绪；该字符串只是内部标记，**不是、也不得成为公开 `error_code`**；
- 契约 4.2 有内部码 `HARNESS-503`，标注“内部控制；公开映射待确认”；
- 契约 4.3 规定内部码默认不透传，公开响应只使用逐接口错误码表列出的码；
- 契约附录 A 已按 Spec 8.1/13.1 溯源把本表 8 个接口的公开 503 映射、`details` 与验收口径固定下来，details 结构已回写 Spec 9.1，未新增错误码。

因此实现返回领域 503 码，前端统一显示“依赖未就绪”。该事项不是后端缺陷，不修改后端；口径差异已记入《02-契约偏差记录》C-01。

### 内部标记与公开码边界

| 字符串 | 使用位置 | 是否允许进入公开 `error_code` |
|---|---|---|
| `HARNESS_NOT_READY` | 后端 Harness 桩/适配层内部 `NotImplementedError` | 否 |
| `HARNESS-503` | 契约 4.2 内部码 | 否，按 4.3 默认不透传 |
| `CONN-503` 等 | 公开响应的逐接口领域码 | 是 |
