# 生产级 ETL-Agent 数据集成平台 接口契约

| 项 | 内容 |
|---|---|
| 契约版本 | v1.0 |
| 生成日期 | 2026-10-23 |
| 契约状态 | 已生成，待评审冻结 |
| 契约基线 | Spec 第 9.2 节 API-01～API-18；PRD 第 8 节 18 个接口 |
| 冲突裁决 | PRD 与 Spec 冲突以 PRD 为准；Spec 细化不改变路径与语义；Spec/PRD 未定义项标“待确认” |
| 需求优先级 | 不设置；P0-P3 仅指 PDP 风险等级 |
| 契约定位 | 前后端、Worker、Harness 之间唯一接口事实源；实现不得偏离本契约 |
| 路径变更 | 不新增、不删除、不改写任何接口路径 |

## 1. 契约总则

### 1.1 协议与版本

| 项 | 契约约束 |
|---|---|
| 协议 | HTTP/JSON；文件上传接口使用 `multipart/form-data` |
| 字符集 | UTF-8 |
| 时间 | ISO 8601 带时区，示例 `2026-10-23T10:00:00+08:00` |
| 版本 | 路径前缀 `/api/v1`；破坏性变更升 `/api/v2`，不原地改语义 |
| 路径基线 | Spec 9.2 原路径逐字保留；路径中的 `{id}`、`{version_id}` 等占位符不改名 |
| 资源标识 | 响应统一返回资源 `id` 与业务键；路径参数语义在逐接口“路径参数”表标注 |
| 包络 | 所有 JSON 响应使用统一包络 `{"data": ..., "correlation_id": "..."}`；Spec 9.2 列出的字段置于 `data` 内 |
| 空响应 | `204 No Content` 不返回包络 |
| OpenAPI | 本契约不附 OpenAPI；若后续输出 OpenAPI 3.1，必须与本文件逐接口表一致，不一致以本文件为准 |

### 1.2 命名与类型

| 项 | 契约约束 |
|---|---|
| 字段命名 | `snake_case` |
| 枚举值 | 小写蛇形；Spec/PRD 已定义的 `L0/L1/L2`、`P0-P3`、`ROLLBACK` 保留原样；Spec 4.5/4.6 状态机大写值（`PENDING`/`APPROVED`/`REJECTED`/`PREPARED`/`COMMITTED` 等）保留原样 |
| 布尔 | 使用 `is_` / `has_` 前缀；Spec 已定义的 `readonly`、`success`、`design_ready` 保留原名 |
| 类型集合 | `string`、`integer`、`number`、`boolean`、`object`、`array`、`enum` |
| 数组 | 必须写 item 类型；未定义 item 结构标“待确认” |
| 对象 | 必须写子字段；未定义子字段标“待确认”，不得以自由对象替代 |
| 必填 | `required` / `optional` / `conditional`；`conditional` 必须写触发条件 |
| 空值 | 未定义的 `null` 语义不得由实现自行约定；标“待确认” |

### 1.3 分页、排序与过滤

| 项 | 契约约束 |
|---|---|
| 分页字段 | `page`、`page_size`、`total`、`items` |
| 分页默认值 | 待确认；Spec 未给默认值 |
| `page_size` 上限 | 待确认；不得擅自定值 |
| 排序 | Spec 未定义排序参数；本契约不新增排序能力；排序需求列入第 10 章待确认（待 Spec 增补后再生效） |
| 过滤 | 仅允许逐接口“查询参数”表显式列出的字段；不允许任意字段过滤 |
| 列表包络 | `data` 内含 `items`、`total`、`page`、`page_size` |

### 1.4 契约定位与冻结

| 项 | 契约约束 |
|---|---|
| 唯一事实源 | 前端、后端、Worker、Harness 的接口字段、错误码、幂等、审计、脱敏均以本契约与 Spec 为准 |
| 实现偏离 | 视为缺陷；不得以“前端聚合”“临时字段”“内部约定”替代契约 |
| 契约变更 | 必须版本化，规则见第 11 章 |
| 未定义能力 | 只能列入第 10 章“待确认”，不得补造接口、字段、错误码、审计事件 |
| 原型数据 | 200MB、2M 行、5% 错误率、10min、99.0 分等均为演示值，不进入契约 |

### 1.5 Harness 标注定义

| 标注 | 取值 | 定义 |
|---|---|---|
| 是否经 Harness | 是 / 否 / 部分 | “是”= 该接口的副作用或安全决策必须经 Harness 组件；“部分”= 仅部分步骤经 Harness；“否”= 不调用 Harness |
| 是否副作用 | 是 / 否 | “是”= 产生外部状态变更或控制面持久化写入；“否”= 纯读取或只读外部调用，不改变外部状态；只读调用仍须经 Harness |
| 是否需要 Capability | 是 / 否 / 不适用 / 待确认 | “是”= 需要 Ed25519 单次执行令牌；“不适用”= 非执行类接口 |
| 是否写 Ledger | 是 / 否 | “是”= 产生 Spec 12.2 目录内审计事件并进入 Evidence Ledger；“否”= 不写 Ledger |

### 1.6 安全边界

| 约束 | 契约要求 |
|---|---|
| Secret | 契约不出现 Secret 明文、密码、Vault 令牌；仅允许 `secret_ref` 引用与 `secret_state` 状态 |
| Capability | 不出现 Capability 明文；仅允许 `capability_digest` / `token_digest` / `jti` 摘要 |
| 敏感样本 | 不出现原始手机号、邮箱、姓名、证件号、主机凭据；示例一律脱敏 |
| 错误详情 | `details` 不得含 Secret、令牌、堆栈、完整主机、原始敏感值 |
| 日志 | `recent_logs` 必须服务端脱敏；不得返回密码、令牌、连接串凭据 |
| 示例 | 全部为合成值；示例 ID 如 `prj_demo_001`、`conn_demo_001` 不对应真实资源 |

## 2. 全局约定

### 2.1 请求头

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 是（API-01 待确认 P-27） | 认证凭据；格式与方案待确认 P-26；契约不约定令牌格式 |
| `X-Correlation-Id` | 否 | 客户端链路 ID；缺省由服务端生成；服务端必须回传同一值 |
| `Idempotency-Key` | 写接口必填（API-05、API-10 例外，见逐接口表） | 幂等键；同一键同一载荷返回首次结果；同一键不同载荷返回 `409`；请求体携带 `idempotency_key` 的接口（API-13/14/16/17/18）须与请求头一致，不一致返回 `422`（Spec 9.1） |
| `Content-Type` | 是 | JSON 接口 `application/json`；API-07 `multipart/form-data` |
| `Accept` | 否 | 默认 `application/json` |

### 2.2 响应头

| 响应头 | 约束 |
|---|---|
| `X-Correlation-Id` | 必须回传；成功与失败响应均包含 |
| `Content-Type` | `application/json; charset=utf-8`；`204` 除外 |
| 禁止暴露 | 不返回服务端版本、内部主机名、堆栈、依赖地址、Secret、令牌 |

### 2.3 成功结构

```json
{
  "data": {
    "id": "res_demo_001"
  },
  "correlation_id": "corr_demo_001"
}
```

列表接口：

```json
{
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 20
  },
  "correlation_id": "corr_demo_001"
}
```

成功包络结构与列表 `data` 内回显 `page_size` 依据 Spec 9.1 成功结构定义。

### 2.4 错误结构

```json
{
  "error_code": "APR-403",
  "message": "self approval forbidden",
  "correlation_id": "corr_demo_001",
  "details": {
    "reason": "SELF_APPROVAL_FORBIDDEN"
  }
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `error_code` | string | 是 | 必须是 Spec 已定义错误码；不得自造 |
| `message` | string | 是 | 脱敏、可读；不得含堆栈、Secret、内部地址 |
| `correlation_id` | string | 是 | 与响应头一致 |
| `details` | object | 是 | 仅放脱敏后的结构化原因；子字段按接口定义；不得含原始敏感值 |

### 2.5 状态码

| HTTP | 语义 | 契约使用 |
|---|---|---|
| 200 | 成功 | GET、PUT、POST 非创建类成功 |
| 201 | 创建 | 创建资源成功（API-03/07/08/09/12/14/18；Spec 9.1） |
| 204 | 无内容 | 无响应体操作（Spec 未定义；当前无接口使用） |
| 400 | 参数错误 | 请求语法、头、JSON 结构错误 |
| 401 | 未认证 | 缺失/无效认证凭据 |
| 403 | 无权限 | 角色、项目隔离、职责槽、自批拒绝 |
| 404 | 不存在 | 资源不存在或不属于当前项目 |
| 409 | 冲突 / 状态不允许 | 幂等冲突、重复决策、状态机不允许 |
| 410 | 过期 | Capability、Replay Guard 键过期 |
| 413 | 超限 | 文件大小超限；上限待确认 P-15 |
| 422 | 语义校验失败 | 字段语义、门禁、指纹、Schema 校验失败 |
| 424 | 依赖失败 | Tool Broker 依赖失败 |
| 429 | 限流 | 限流触发；阈值待确认（Spec 未定义限流；本节为契约扩展提案，评审通过前不构成 Spec 约束） |
| 500 | 内部错误 | 未预期服务端错误；不得返回堆栈 |
| 503 | 依赖不可用 | Vault、Redis、SeaTunnel、Provider、Broker 不可用 |
| 504 | 依赖超时 | 外部工具或依赖超时 |

### 2.6 限流

| 项 | 契约约束 |
|---|---|
| 必设限流接口 | 所有写接口；所有 Harness 相关接口（API-05、API-06、API-07、API-12、API-14、API-16、API-17、API-18） |
| 限流维度 | 至少 `actor_id + project_id + endpoint`；API-14/16/17/18 追加 `tool` 或 `operation` |
| 阈值 | 待确认；Spec/PRD 未给数值 |
| 超限响应 | `429`；`error_code` 待确认（Spec 13.1 未定义限流专用码） |
| 响应头 | `Retry-After` 是否返回待确认 |
| 依据 | Spec 未定义限流；本节为契约扩展提案，评审通过前不构成 Spec 约束 |

### 2.7 审计与脱敏

| 项 | 契约约束 |
|---|---|
| 写接口 | 每个写接口至少声明一条 Spec 12.2 审计事件；无对应事件的写接口列入第 10 章 |
| 只读接口 | 默认不写 Ledger；API-05/06/07 虽以 POST 触发只读受管工具，按 Spec 仍写领域审计 |
| 脱敏 | 响应字段逐接口标注“是否脱敏”与规则；脱敏失败时不展示该字段 |
| 禁止 | 不得返回未脱敏样本、Secret、密码、Capability 明文、完整主机凭据 |
| 示例 | 每个接口至少一个请求示例、一个成功响应示例、一个失败响应示例 |

## 3. 认证与授权约定

### 3.1 认证

| 项 | 契约约束 |
|---|---|
| 认证机制 | 待确认 P-26；本契约只约定“必须认证”，不约定令牌格式、登录方式、会话策略 |
| 认证头 | `Authorization`；方案前缀与凭据格式待确认 P-26 |
| 失败 | `401 AUTH-401`；不得泄露账号是否存在 |
| API-01 | 是否公开待确认 P-27；确认前按“必须认证”实现，公开只读仅作为建议 |
| 服务主体 | Worker/Harness 内部调用不使用本契约 HTTP 角色；不得以服务主体替代用户审批 |

### 3.2 项目隔离

| 规则 | 契约约束 |
|---|---|
| 归属 | 所有资源必须可归属 `project_id`；路径含 `project_id` 的以路径为准，其余从认证上下文解析 |
| 跨项目 | 返回 `403 AUTH-403`；不得返回 `404` 掩盖存在性，除非资源本身不存在 |
| 查询 | 列表接口只返回当前项目资源；不得接受任意 `project_id` 过滤 |
| 写入 | 创建请求中的 `project_id` 必须与认证上下文项目一致；不一致 `403` |

### 3.4 强制职责分离

| 规则 | 服务端强制点 | 失败码 | 审计事件 |
|---|---|---|---|
| 申请人禁止自批 | 审批决策比对 `actor_id` 与申请人；申请人身份来源待确认 P-10 | `APR-403 SELF_APPROVAL_FORBIDDEN` | `approval.self_approval_blocked` |
| 同一人不得占多个审批职责槽 | Preparation 分配与审批决策校验两个审批人不同且均非申请人 | `APR-409 ROLE_SLOT_CONFLICT` | `approval.slot_conflict_blocked` |
| 数据/安全审批人独立 | 校验 `project_role_grants` | `APR-403 ROLE_GRANT_MISSING` | `approval.role_denied` |
| 审批不可撤销 | 已决策记录禁止更新 | `APR-409 DECISION_IMMUTABLE` | `approval.decision.recorded` |
| 不得绕过审批执行 | Commit 校验 2/2；Tool Broker 拒绝无 Preparation 的执行 | `CMT-409 APPROVAL_INCOMPLETE`、`TB-403 CAPABILITY_REQUIRED` | `tool.call.rejected` |

### 3.5 授权判定顺序

| 顺序 | 校验 | 失败结果 |
|---|---|---|
| 1 | 认证 | `401 AUTH-401` |
| 2 | 项目成员与项目归属 | `403 AUTH-403` |
| 3 | 角色/职责槽 | `403 ROLE-403` / `403 APR-403` |
| 4 | 资源归属与状态 | `404` / `409` |
| 5 | 自批与槽位独立性 | `403 APR-403` / `409 APR-409` |
| 6 | 指纹、审批事实、门禁 | `409` / `422` |

前端隐藏按钮不构成安全边界；所有写操作必须服务端复核。

说明：判定顺序为契约细化；Spec 未定义判定顺序，冲突时以 Spec 12.1/9.1 为准。

## 4. 错误码总表

### 4.3 错误码使用规则

| 规则 | 约束 |
|---|---|
| 唯一来源 | 公开响应只使用逐接口“错误码”表列出的码；不得返回未列出的内部码 |
| 领域码优先 | 有领域错误码时返回领域码，不以 `API-*` 掩盖 |
| 内部码透传 | CAP/RG/TB/OBX/EL/PDP/HARNESS/SEC/DIAG 内部码默认不透传；映射规则待确认 |
| 错误详情 | `details` 只放脱敏字段；不得含 Secret、令牌、堆栈、SQL、完整主机 |
| 重试 | 仅 503/504 且标注“可重试”的码允许客户端退避重试；执行类工具 `UNKNOWN` 不自动重试 |
| 错误码变更 | 只增不改；废弃码保留并标 `deprecated` |
